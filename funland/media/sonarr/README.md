# Sonarr

This directory contains the manifests for deploying [Sonarr](https://sonarr.tv/), a TV series collection manager.

## Image

This deployment uses the `linuxserver/sonarr` Docker image.

## Access / SSO

Sonarr is **not** exposed directly. `http-route.yaml` routes `sonarr.batlab.io` (internal gateway only) to the shared `authentik-proxy` Service in the `authentik` namespace (see `funland/authentik/authentik-proxy/`), which reverse-proxies to this app's own Service only after Authentik authenticates the request. Access is restricted to the `media-admins` Authentik group.

Sonarr trusts the outpost's authentication via `SONARR__AUTH__METHOD=External` so it doesn't also show its own login screen.

## Storage

- **Config:** Longhorn PVC (`sonarr-config`, 5Gi) for `/config`.
- **Media library:** the same NFS export Jellyfin uses (`192.168.11.13:/mnt/tank/media/library`), mounted **read-write** at `/media` (Jellyfin mounts it read-only) so Sonarr can organize/hardlink imports into the library.

## Dependencies

- **[External Secrets](https://external-secrets.io/):** Pulls the Sonarr API key from 1Password.
- **[Authentik](https://goauthentik.io/):** SSO via the shared proxy outpost (see above).

## Secrets

`sonarr-secret` ExternalSecret provides `api_key`, sourced from the `sonarr` 1Password item's `api_key` property. This value is self-generated (not auto-generated by Sonarr) and pre-seeded via the `SONARR__AUTH__APIKEY` env var — Recyclarr and Prowlarr's app-linking both reference this same key.

## Manual setup (no declarative equivalent)

- In Sonarr's UI, add your download client under **Settings → Download Clients** (this repo does not deploy or reference a downloader).
- The completed-download import path (wherever your downloader writes) must be reachable from this pod — ideally a subpath of the same NFS export mounted at `/media` above, so hardlinking works. If it isn't, a second NFS/volume mount will be needed.
