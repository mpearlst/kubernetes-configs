# Radarr

This directory contains the manifests for deploying [Radarr](https://radarr.video/), a movie collection manager.

## Image

This deployment uses the `linuxserver/radarr` Docker image.

## Access / SSO

Radarr is **not** exposed directly. `http-route.yaml` routes `radarr.batlab.io` (internal gateway only) to the shared `authentik-proxy` Service in the `authentik` namespace (see `funland/authentik/authentik-proxy/`), which reverse-proxies to this app's own Service only after Authentik authenticates the request. Access is restricted to the `media-admins` Authentik group.

Radarr trusts the outpost's authentication via `RADARR__AUTH__METHOD=External` so it doesn't also show its own login screen.

## Storage

- **Config:** Longhorn PVC (`radarr-config`, 5Gi) for `/config`.
- **Media library:** the same NFS export Jellyfin uses (`192.168.11.13:/mnt/tank/media/library`), mounted **read-write** at `/media` (Jellyfin mounts it read-only) so Radarr can organize/hardlink imports into the library.

## Dependencies

- **[External Secrets](https://external-secrets.io/):** Pulls the Radarr API key from 1Password.
- **[Authentik](https://goauthentik.io/):** SSO via the shared proxy outpost (see above).

## Secrets

`radarr-secret` ExternalSecret provides `api_key`, sourced from the `radarr` 1Password item's `api_key` property. This value is self-generated (not auto-generated by Radarr) and pre-seeded via the `RADARR__AUTH__APIKEY` env var — Recyclarr and Prowlarr's app-linking both reference this same key.

## Manual setup (no declarative equivalent)

- In Radarr's UI, add your download client under **Settings → Download Clients** (this repo does not deploy or reference a downloader).
- The completed-download import path (wherever your downloader writes) must be reachable from this pod — ideally a subpath of the same NFS export mounted at `/media` above, so hardlinking works. If it isn't, a second NFS/volume mount will be needed.
